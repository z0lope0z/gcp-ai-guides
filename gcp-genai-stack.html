2. Model Garden: which model, and how to run it

Model Garden is the catalogue of first-party (Gemini, Imagen, Veo, Gemma), partner (for example Anthropic Claude, Meta Llama, Mistral) and open models. Some are offered as models as a service (MaaS): a serverless API you pay per token. Others you deploy to your own endpoint with chosen hardware, paying for the nodes.

NeedPick
Hardest reasoning, long documents, complex multimodalGemini Pro tier
Low latency and cost at high volumeGemini Flash or Flash-Lite tier
Images / video generationImagen / Veo
Open weights, run in your VPC, customize freelyGemma or another open model deployed from Model Garden to an endpoint or GKE
A specific partner model the team standardized onThat model through MaaS
Text embeddings for search or RAGGemini embedding / text-embedding models

Three ways to run a model

How you run itWhat it meansPay forChoose when
Model as a service (MaaS)Serverless API managed by Google; nothing to deployTokens (or Provisioned Throughput)Fastest start, spiky traffic, no infrastructure team
Self-deploy to an Agent Platform endpointOne-click deploy of open weights onto GPUs/TPUs you chooseNode hours, even when idleOpen model, custom weights (LoRA), data in your VPC, steady high traffic
Deploy on GKERun the model yourself with vLLM, TGI or similarCluster nodesExisting Kubernetes platform, maximum control, multi-model serving

Choosing between Gemini tiers

  • Pro: hardest reasoning, long-context analysis, complex coding and agents. Highest cost and latency.
  • Flash: balanced default for production at scale.
  • Flash-Lite: highest volume and lowest cost: classification, extraction, routing.
  • Choose by evaluating on your own task: start with the cheapest tier that meets the quality bar, not the biggest.
  • Pin a specific model version in production; aliases that auto-update can change behaviour under you.

Temperature 0 reduces variation but doesn't guarantee identical outputs. For reliability, combine low temperature with structured output and evaluation.

5. Structured output and function calling

Structured output

Set response_mime_type="application/json" and a response_schema (OpenAPI-style or JSON Schema). The model is constrained to produce valid JSON matching the schema: enums for categories, required fields, types. This is the answer to "the app keeps failing to parse the model's JSON".

from google import genai
from google.genai import types

client = genai.Client(vertexai=True, project="PROJECT_ID", location="global")
resp = client.models.generate_content(
    model="gemini-flash-model-id",
    contents="Ticket: 'App crashes when I upload a photo.'",
    config=types.GenerateContentConfig(
        temperature=0,
        response_mime_type="application/json",
        response_schema={"type": "OBJECT",
                         "properties": {"category": {"type": "STRING", "enum": ["bug", "billing", "account", "other"]},
                                        "urgent": {"type": "BOOLEAN"}},
                         "required": ["category", "urgent"]}))
print(resp.text)   # {"category": "bug", "urgent": false}

Function calling (tool use)

  1. You declare functions (name, description, parameter schema).
  2. The model decides whether to call one and returns a function call with arguments. It doesn't execute anything.
  3. Your code runs the function (an API, a database query) and sends back the result as a function response.
  4. The model uses the result to answer, or calls another function.
  • Calling modes: AUTO (model decides), ANY (must call one; optionally restrict to allowed names), NONE.
  • Parallel function calls: several independent calls in one turn.
  • Built-in tools: Grounding with Google Search, code execution, URL context, enterprise search.
  • MCP (Model Context Protocol) servers expose tools to agents in a standard way; A2A (Agent2Agent) lets agents call other agents.
Validate function arguments and enforce authorization in your code. The model can be manipulated (prompt injection) into requesting calls a user shouldn't make; least-privilege tool credentials limit the blast radius.

6. Adapting a foundation model: the tuning ladder

TechniqueWhat it changesUse when
Prompt engineeringInstructions, examples (few-shot), system instructions, output schemaAlways first: cheapest and fastest to iterate
Grounding / RAG (retrieval-augmented generation)Adds retrieved facts to the prompt: Grounding with Google Search, Agent Search, RAG Engine, Vector SearchThe model needs fresh or private facts, or must cite sources and hallucinate less
Supervised fine-tuning (parameter-efficient, adapter-based)Model behaviour: style, format, domain task, classification labelsPrompting can't reach the quality, or prompts are getting long and costly; you have hundreds or more labelled examples
Preference tuning / reinforcement learningAligns with human preferencesYou have preference pairs; quality judged by people
DistillationTeaches a small model to imitate a large oneNeed Pro-like quality at Flash-like cost and latency
Fine-tuning doesn't teach a model new facts reliably and doesn't keep them fresh. "The answers must reflect documents that change daily" is a grounding/RAG problem, not a tuning problem.

Supervised fine-tuning in practice

TopicWhat to know
DataJSONL of example conversations (user input, ideal model output), in Cloud Storage. Quality and consistency beat volume; start with ~100–500 good examples
MethodParameter-efficient (adapter, LoRA-style) tuning on Gemini; full or LoRA tuning for open models from Model Garden
HyperparametersEpochs, adapter size, learning-rate multiplier; watch validation loss for overfitting
OutputA tuned model served from its own endpoint; call it like the base model
EvaluateAgainst the base model with prompting, on a held-out set, with Agent Platform Evals
CostTuning job cost plus serving the tuned model; re-tune when the base model version retires
Decision: knowledge problem (facts, freshness, citations) → grounding/RAG. Behaviour problem (format, style, a narrow task's accuracy, shorter prompts) → tuning. Cost/latency problem with a big model working well → distillation or a smaller tier.

7. Agents: ADK, Agent Runtime, Sessions and Memory Bank

An agent is a model in a loop: it plans, calls tools, reads results and continues until the task is done. Use agents when the steps aren't known in advance; use a fixed workflow (a chain or pipeline) when they are.

PieceRole
ADKDefine agents, tools, sub-agents and workflow agents (sequential, parallel, loop) in Python or other languages; run locally
Agent RuntimeDeploy ADK (or LangGraph, LangChain and other framework) agents as a managed, autoscaling service with IAM, logging and tracing
SessionsStores conversation history and state for one interaction
Memory BankLong-term memory across sessions: extracts and recalls user facts and preferences
Code ExecutionSandboxed environment where an agent runs code it writes
Agent GardenSamples and templates to start from
Gemini EnterpriseEmployee-facing app where agents are shared and used across the company

Agent design choices the exam probes

  • Single agent with tools first; split into multiple agents only when roles, tools or prompts genuinely differ.
  • Short-term state in Sessions; durable user facts in Memory Bank; business data stays in your databases behind tools.
  • Guard tools: least-privilege service accounts, human approval for irreversible actions, Model Armor on inputs and outputs.
  • Evaluate trajectories (which tools were called, in what order), not only the final answer. See agent evaluation.

9. Cost, latency and availability

LeverEffect
Smaller model tier (Flash, Flash-Lite)Lower cost and latency; evaluate quality on your task first
Context cachingReuse a large, repeated prefix (a manual, a codebase) across requests at a discount, with lower latency
Batch inferenceAsynchronous jobs over BigQuery or Cloud Storage at roughly half the online price; minutes to hours of latency
Provisioned ThroughputReserved capacity for predictable, production traffic; avoids 429s under shared quota
Global endpointRoutes to available regions for higher availability (when data residency allows)
Retry with exponential backoffCorrect response to 429 Resource exhausted under dynamic shared quota
Streaming responsesBetter perceived latency (time to first token) for chat
Shorter prompts, max_output_tokens, structured outputFewer tokens billed; parseable JSON without retries
Discount sizes and quota behaviour are set by current pricing pages. Learn the direction (batch and caching cost less; provisioned throughput buys reliability), not the exact percentages.

Context caching in detail

  • Implicit caching: automatic discount when requests share a long prefix; put the stable content (manual, instructions) first and the variable question last.
  • Explicit caching: create a cache object with a time to live; pay a storage fee per hour; reference it from many requests.
  • Worth it when the same large context is reused many times within the TTL.

11. Lab: a structured, tool-using Gemini app

  1. In Agent Studio, write a system instruction for a support triage assistant. Try zero-shot, then add three examples; note which edge cases improve.
  2. In a notebook with the Google Gen AI SDK, request structured output with an enum category and boolean urgent; run 50 tickets and count parse failures (should be zero).
  3. Declare a function get_order_status(order_id); implement it as a stub; confirm the model returns a function call and that your code executes it.
  4. Compare a Flash-Lite and a Flash tier on the same 50 tickets: accuracy, latency and token counts from usage metadata.
  5. Put a 30-page policy document first in the prompt and send 20 questions; compare cached token counts and latency between the first and later requests.
  6. Wrap the assistant as an ADK agent with the tool and deploy it to Agent Runtime; enable Sessions and check that a follow-up question uses earlier context.

Clean up: delete the Agent Runtime deployment, explicit caches and any tuned-model endpoints.

17. Common gotchas in one list

  1. Tuning changes behaviour, not knowledge. Fresh or private facts need grounding.
  2. The model never executes functions; your code does, and must check authorization.
  3. Structured output beats "please return JSON" for reliable parsing.
  4. Start with the cheapest tier that passes evaluation, not the biggest model.
  5. MaaS for no-ops and spiky traffic; self-deploy for custom weights, VPC control or steady load.
  6. Pin model versions and re-run evaluations before upgrading.
  7. 429s mean quota pressure: exponential backoff, then Provisioned Throughput for steady load.
  8. Batch inference for big, non-urgent jobs: discounted and asynchronous.
  9. Context caching needs the shared content at the start of the prompt.
  10. Sessions are short-term; Memory Bank is long-term.
  11. Prefer one agent with tools before multi-agent designs.
  12. Temperature 0 isn't determinism; evaluate and constrain output.
  13. Long context isn't free: every request pays for all tokens unless cached.
