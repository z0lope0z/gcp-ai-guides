1. Bias, variance and generalization

A model's job is to generalize: do well on data it hasn't seen. Its error on new data comes from three sources:

SourceMeaningSymptom
BiasThe model is too simple, or its assumptions are wrong, so it misses real patternsUnderfitting: high error on training and validation data
VarianceThe model is too sensitive to the particular training sample; it learns noiseOverfitting: low training error, much higher validation error
Irreducible errorNoise in the labels or missing information no model can recoverA floor that more modelling can't break

Making a model more flexible usually lowers bias and raises variance; constraining it does the reverse. The goal is the capacity where validation error is lowest.

A student who memorizes past exam answers (high variance) aces practice papers and fails new questions. A student who learned only one rule of thumb (high bias) does badly on both. You want the one who learned the underlying ideas.

Multi-class averaging

  • Macro average: mean of per-class metrics; every class counts equally (good when rare classes matter).
  • Micro average: pool all decisions; dominated by frequent classes (equals accuracy for single-label problems).
  • Weighted average: per-class metrics weighted by class frequency.

7. ROC AUC vs PR AUC: why imbalance changes the answer

Both curves sweep the decision threshold from high to low.

  • ROC curve: true positive rate (recall) against false positive rate. ROC AUC is the probability that a random positive is scored above a random negative. 0.5 is random; 1.0 is perfect.
  • PR curve: precision against recall. PR AUC (average precision) is the area under it. A random model scores about the positive rate (0.01 at 1% positives), not 0.5.

Worked example

1,000,000 transactions, 1% fraud (10,000 positives). A model at some threshold has recall 80% and FPR 1%.

QuantityValue
True positives0.80 × 10,000 = 8,000
False positives0.01 × 990,000 = 9,900
Precision8,000 / 17,900 ≈ 45%

On the ROC curve, (FPR 1%, TPR 80%) looks excellent. But more than half the alerts are false. If fraud were 0.1%, the same TPR and FPR would give precision ≈ 7%. ROC doesn't move when prevalence changes, because both of its rates are computed within one class each; precision mixes the two classes, so PR curves show what an analyst reviewing alerts experiences.

Imbalanced data: use PR AUC (and precision at a required recall, or recall at a required precision). ROC AUC is fine for balanced classes and for comparing ranking quality, but on rare-event problems it can look great while the model is unusable.
PR AUC values aren't comparable across datasets with different positive rates; the baseline moves with prevalence. Compare models on the same test set.

9. Choosing the threshold

Models output scores; a threshold turns scores into decisions. The default 0.5 is arbitrary. Choose the threshold on validation data from what each error costs.

  1. Price each error: a missed fraud costs the transaction amount; a false alarm costs review time and customer friction.
  2. For each candidate threshold, compute expected cost = FN × costFN + FP × costFP.
  3. Pick the minimum, or the threshold that meets a hard constraint (recall ≥ 95%, or at most 500 alerts per day for the review team).
  • Raising the threshold: fewer positives, usually higher precision and lower recall.
  • BigQuery ML: ML.ROC_CURVE and ML.CONFUSION_MATRIX(MODEL m, (SELECT ...), STRUCT(0.3 AS threshold)); predictions accept a threshold too.
  • Thresholds can differ per segment only if policy and fairness review allow it.

11. Calibration

A model is calibrated if, among cases it scores 0.8, about 80% are positive. Ranking (AUC) can be excellent while probabilities are badly off.

TopicDetail
Why it mattersExpected-cost decisions, risk scores shown to people, combining models, pricing
What breaks itClass weights, resampling, boosting, overconfident neural networks, distribution shift
How to checkReliability diagram (predicted vs observed rate per bin), Brier score, log loss
How to fixPlatt scaling (logistic fit on scores), isotonic regression (more flexible, needs more data), temperature scaling for neural networks; fit on validation data

18. Common gotchas in one list

  1. Both errors high = bias; big gap = variance. The fixes are opposite.
  2. More data fixes variance, not bias.
  3. Regularization and early stopping fight overfitting; they make underfitting worse.
  4. PR AUC for imbalanced data. ROC AUC ignores prevalence and can look great while precision is terrible.
  5. PR AUC's random baseline is the positive rate, not 0.5.
  6. Never keep the 0.5 threshold by default; pick it from error costs on validation data.
  7. Precision when false positives hurt, recall when misses hurt.
  8. Class weights and resampling break calibration; recalibrate before using probabilities.
  9. Tuning on the test set makes the test score optimistic.
  10. Time series: no shuffling; backtest with rolling windows.
  11. RMSE punishes big misses; MAE is robust; MAPE breaks near zero.
  12. Macro averages expose rare-class failure that accuracy hides.
  13. Offline metrics pick candidates; A/B tests decide launches.
  14. Validation better than training: check dropout effects and leakage before celebrating.
